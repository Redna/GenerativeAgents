# GENERATIVE AGENTS SANDBOX - HANDOVER MEMORY

This file contains critical context, architectural decisions, and operational knowledge for any agent picking up development on the Generative Agents Sandbox.

## 1. Project Overview & Current State
**Goal**: Create a standalone sandbox environment to visualize generative agents in a 2D world (Phaser.js) driven by a Python backend.
**Current Status**: 
-   **Frontend**: Fully functional Phaser 3 UI with split-pane layout (Map Left, Sidebar Right).
-   **Backend**: Mock Python server (`mock_server.py`) simulating agent data via Socket.IO.
-   **Environment**: Uses `.venv` virtual environment for Python dependencies.
-   **Integration**: Successful end-to-end communication via local Socket.IO (Port 8000).

## 2. Key Architecture & Files

### Frontend (`frontend/`)
-   **Framework**: Phaser 3 + TypeScript + Vite.
-   **Entry Point**: `src/scenes/game.ts` (Main Game Loop & Rendering).
-   **UI Logic**: `src/ui.ts` (Sidebar management, DOM manipulation).
-   **Communication**: `src/connector/simulationConnector.ts` (Socket.IO client wrapper).
-   **Data Types**: `src/connector/dtos.ts` (Shared DTOs between FE/BE).

### Backend (`src/generative_agents/`)
-   **Mock Server**: `mock_server.py`
    -   Uses `python-socketio` and `aiohttp`.
    -   Simulates game loop and broadcasts state updates (`update` event).
    -   **Port**: 8000 (Hardcoded). Note: User sometimes refers to 8080, but process runs on 8000.

### Scripts
-   **`run_sandbox.sh`**: Main entry point. Usage: `./run_sandbox.sh mock` (or `real`).
    -   Handles process management (starts BE & FE).
    -   **Auto-detects `.venv`**: Prefers `.venv/bin/python` if available.

## 3. Implemented Features (Verified)

### A. Visuals & Map
-   **Map**: 'The Ville' (`the_ville_jan7.json`).
-   **Zoom/Pan**: Mouse wheel zooms, drag pans the camera.
-   **Highlighting**: 
    -   "FIFA-style" red pulsing circle under selected agent's feet.
    -   Graphic Logic: `game.ts -> updateHighlight()`. Uses alpha sine wave for pulsing.
    -   Z-Index: Layered correctly (Ground < Highlight < Agent).

### B. Agent Interaction
-   **Selection**: Clicking agent in sidebar OR map selects them.
-   **Camera Follow**: 
    -   Camera smoothly tracks selected agent (`camera.startFollow`).
    -   **Break Follow**: Manual pan (drag) breaks the lock.
-   **Deselection**:
    -   "Unfocus Camera" button in sidebar.
    -   Clears highlight, stops camera follow, hides details panel.
    -   Event: `deselect-agent`.

## 4. Operational Knowledge & Gotchas

### Running the Sandbox
```bash
./run_sandbox.sh mock
```
*Note: Ensure `.venv` is active or configured. The script handles this, but manual pip installs need `.venv/bin/pip`.*

### Python Dependencies
-   Requires: `python-socketio`, `aiohttp`.
-   Install: `.venv/bin/pip install python-socketio aiohttp`.

### Common Issues
-   **Port Conflicts**: If the server fails to start, check port **8000**.
    -   Command: `lsof -i :8000` (or sometimes 8080 mixed up by user).
    -   Kill: `kill -9 <PID>`.
-   **Asset Loading**: If sprites are missing, ensure `frontend/public/assets` matches the `game.ts` loader paths.
-   **Socket Disconnects**: If frontend loops connecting, backend is likely crashed or port blocked.

## 6. Phase 1: Decouple Perception & Simulation Loop (Feb 2026)

### Objective
Decouple the agent's internal logic from the simulation loop to allow for cleaner state updates and easier debugging.

### Key Changes
- **SimulationEngine**: Introduced `src/generative_agents/core/simulation_engine.py` to handle the game loop, state broadcasting, and agent orchestration. It acts as the single source of truth for the world state.
- **Percept Dataclass**: created `src/generative_agents/core/percept.py` to encapsulate all sensory data (local tiles, nearby agents) passed to an agent.
- **Agent Refactor**:
    -   Added `agent.perceive(percept)`: Agents now receive a `Percept` object instead of querying the global `Maze` directly.
    -   Added `agent.run_step()`: Replaces the ambiguous `update()` method. This method executes the agent's cognitive cycle (Perceive -> Plan -> Act) in a linear, predictable manner.
    -   Removed direct `Maze` dependency from the `Agent` class, improving testability.

## 7. Phase 2: Remove LangGraph & Architecture Simplification (Feb 2026)

### Objective
Simplify the agent's execution flow by removing the complex graph-based orchestration (`langgraph`) in favor of standard Python control flow.

### Key Changes
- **Removed LangGraph**: Deleted all `langgraph` dependencies and graph definitions. The execution flow is now imperative and contained within `Agent.run_step()`.
- **Deleted AgentRunner**: Removed the `AgentRunner` and `executor` abstractions which added unnecessary complexity for a single-agent-per-process model (or simple loop). The `SimulationEngine` now calls `agent.run_step()` directly.
- **Cognitive Components**: Refactored `perception`, `plan`, `reflection`, etc. to be standalone functions or classes that are called sequentially by the agent, rather than being nodes in a graph.

## 8. Phase 3: DSPy Integration (Feb 16, 2026)

### Key Achievements
- **DSPy 3.1.3 Integration**: Successfully configured the backend to use DSPy for all LLM interactions.
- **Local LLM**: Configured to use **Ollama** with `qwen2.5:4b` model (running locally on port 11434) via `dspy.LM`.
- **Pipeline Migration**: Migrated **24** conversational pipelines from the legacy `grammar_llm_pipeline` (which used Groq/Instructor) to `dspy.ChainOfThought` with strictly typed Signatures.
    - Examples: `daily_plan`, `decide_to_talk`, `action_location_*`, `identity`, etc.
- **Legacy Cleanup**: Removed `grammar_llm_pipeline.py` and its dependencies (`groq`, `instructor`).
- **Testing**: Updated `tests/test_pipelines_dspy.py` to fully test all migrated pipelines using `unittest.mock.MagicMock` to simulate LLM responses without network calls.

### Architecture Update
- **Config**: `src/generative_agents/core/dspy_config.py` handles DSPy setup.
- **Startup**: `src/generative_agents/__main__.py` initializes the DSPy configuration on launch.
- **Signatures**: Each pipeline now uses a dedicated `dspy.Signature` class (e.g., `DecideToTalkSignature`) for type-safe inputs/outputs.

### Next Steps / Hints
1.  **Simulation Verification**: Run the full simulation (`./run_sandbox.sh`) and observe agent behavior. Local LLMs may have higher latency or different "personality" quirks than cloud models.
2.  **Prompt Tuning**: If agents behave erratically, inspect the DSPy Signatures and consider adding `dspy.Teleprompter` (optimizers) to automatically tune prompts.
3.  **Performance**: Monitor the performance impact of the local LLM. If too slow, consider:
    -   Using a smaller model (e.g., `qwen2.5:1.5b` or `llama3.2:3b`).
    -   Moving to a hosted LLM provider if local compute is insufficient.
4.  **Memory Management**: DSPy traces can grow; ensure extensive runs don't consume excessive memory if compiling/optimizing.

## 12. Phase 6: LLM Call Consolidation & Hierarchical Memory (Feb 20, 2026)

### Objective
Reduce per-agent LLM calls from ~7-10/tick to 1-2. Introduce pure-Qdrant graph memory with contextual reranking.

### A. Unified Day Planner (3-5 calls → 1)
- **Before**: WakeUpHourPredictor + DailyPlanGenerator (remember+feelings+reflection+plan) + HourlyScheduler = 3-5 sequential calls.
- **After**: UnifiedDayPlanner(dspy.ChainOfThought(UnifiedDayPlanSignature)) → one call → typed UnifiedDayPlan (wake_up_hour, plan_narrative, hourly_slots).
- **Files**: intelligence/modules/planning.py (added), agents/layers/planning.py (rewritten).

### B. ReAct Tool-Choice Actor (7+ calls → 1)
- **Before**: TalkDecider + ReactionDecider + SectorSelector + ArenaSelector + ObjectSelector + EventParser + EmojiMapper = 7+ sequential calls.
- **After**: ReActActor(dspy.ChainOfThought(AgentStepSignature)) → model picks tool → Python dispatches (0 extra LLM calls).
- **Tools**: move_to(destination) | speak_to(target, opening_line) | wait() | update_action(activity).
- **Files**: intelligence/modules/actor_react.py (new), agents/layers/actor.py (rewritten).

### C. Pure Qdrant Memory + ContextualReranker (N calls → 1 batched)
- **Before**: JSONMemoryRepository with numpy cosine similarity from in-RAM array, JSON file for persistence + graph edges. Rebuilt every startup.
- **After**: QdrantMemoryRepository — everything in Qdrant:
  - Vectors: ANN via query_points() (embedded local client, no server).
  - Graph edges: in payload field related_events: [{id, relation}].
  - Persistence: QdrantClient(path=...) for disk, QdrantClient(location=":memory:") for tests.
- ContextualReranker(dspy.ChainOfThought) — 1 batched LLM call ranks all candidates by contextual relevance.
- AssociativeMemoryLayer 3-stage pipeline: (1) Qdrant ANN top-20 → (2) BFS graph expansion → (3) ContextualReranker top-10.
- expand_fn=self.memory.get_context wired: agent.run_step() → brain.forward() → AssociativeMemoryLayer.
- database.py no longer accesses repo.memories list — all ops via Qdrant.
- **Files**: repository.py, system.py, database.py, agents/layers/retrieval.py (rewritten), intelligence/modules/retrieval.py (new), brain.py, agent.py.

### Qdrant Embedded API Gotchas (critical, version-specific)
- QdrantClient(":memory:") does NOT work → use location=":memory:" or path="/dir".
- .search() is gRPC/server-mode only → use .query_points() for embedded.
- recreate_collection() removed → use collection_exists() + create_collection().
- Local path uses file locking (portalocker) → client.close() before re-opening same path.
- Lazy-load sentence transformer via _get_model() getter to avoid network calls at import time.

## 13. Phase 6 Follow-up: Intelligence Modules Cleanup (Feb 20, 2026)

### Modules removed (all replaced by ReActActor tools)
- ReactionDecider — replaced by ReActActor `wait` / `speak_to` tools
- TalkDecider — replaced by ReActActor `speak_to` tool
- Contextualizer — no callers, deleted
- SectorSelector, ArenaSelector, ObjectSelector (spatial.py) — replaced by ReActActor `move_to(destination)` tool
- spatial.py FILE DELETED entirely

### Modules converted to heuristics (0 LLM calls)
- PoignanceRater → heuristic_poignance(event_type, description)
  Rule: base score from event type + keyword boosts (death/fired/married = +0.08) + penalties (sleeping/idle = -0.06)
  Used in SensoryProcessingLayer._rate_perception_poignancy() — no LLM call.
- EmojiMapper → heuristic_emoji(action_description)
  Rule: keyword pattern match against lookup table of (keywords, emoji) pairs.
  Used in ActorLayer._dispatch_move() and _dispatch_update_action() — no LLM call.

### Modules kept (still active)
- EventParser (perception.py) — triple extraction for ActorLayer dispatch (1 LLM call per move/update action)
- DialogueGenerator, DialogueSummarizer, DialogueMemoer, DialoguePlanner (dialogue.py) — for future multi-turn chat loop
- RelationshipSummarizer (dialogue.py) — reflection pipeline
- reflection.py: ReflectionPointGenerator, InsightGenerator, IdentityFormulator — System 2, fully active
- retrieval.py: ContextualReranker — batched LLM reranking in AssociativeMemoryLayer
